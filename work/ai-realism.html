AI Realism agent

A nightly briefing system that prefers a sourced claim over a vendor announcement.

I built and operate a Python pipeline that researches real-world AI adoption and employment impact, deduplicates what it has already covered, and produces a newsletter plus social drafts. It runs on a schedule through GitHub Actions. The repository is private because it holds the operating workflow, not because the product is hypothetical.

What it actually does

  • Multi-agent orchestration for research, analysis, drafting, and a validation pass.
  • Web research with Tavily, plus X search, with SQLite deduplication and retry logic so the same story does not ship twice.
  • Scheduled execution. A failed run does not silently become a published issue.
  • Editorial constraint: evidence of deployment, jobs impact, and ROI over CEO narrative.

Product decisions

The hard part was not generating text. It was deciding what the system is allowed to assert. The validator pass exists because a fluent draft is not a source. Dedup exists because a daily product that repeats yesterday is worse than no product. The schedule exists so the briefing is an operating system, not a demo I run when someone asks.

This is the same judgment I would bring to an AI feature inside an insurer: define the output, keep the failure visible, and do not let a model email a customer or bind a risk.
