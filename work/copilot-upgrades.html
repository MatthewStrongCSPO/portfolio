Enterprise delivery

Four-agent upgrade pipeline

Java and Spring Boot upgrades, prepared as pull requests a reviewer can audit.

On the Liberty Mutual account I led a team that designed a four-agent GitHub Copilot pipeline for version upgrades, using Visual Studio Code, Copilot, and Model Context Protocol integrations. The pipeline prepares end-to-end upgrade pull requests across tens to hundreds of repositories. It does not add headcount or a new runtime platform.

Why this is product work

  • The unit of delivery is a reviewable pull request, not a chat transcript.
  • Output has to be consistent enough for audit. A one-off prompt is not a process.
  • The human boundary is the review. The agents do not merge themselves into production.
  • The business result is cycle time on a migration that otherwise stalls behind feature work.

Adjacent platform work on the same account: a configuration-driven forms architecture so business users change layouts, trigger rules, and fill-in logic without a deployment, and incident runbooks with time-boxed triage, Lambda alias rollback, and database emergency steps.
